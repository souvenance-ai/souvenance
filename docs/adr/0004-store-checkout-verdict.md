# The checkout: one verdict replaces doctor and finish

The governance layer rebuilds around one question: what forces an agent to close its session cleanly? The legacy split — a doctor that diagnosed corruption and a finish that gated the session's kind-based obligations — answered it with two verbs and two vocabularies. v0.2.0 fuses them into **`checkout()`**: the agent consolidates, the store returns the problems, it resolves them, and the light goes green (`healthy`, zero findings) only when nothing is left. The verdict is **all-or-nothing** — no severity, no arguable silent debt — and **timeless**: no 24h window, and **no check reads a `kind`** — kinds are free metadata tags (prompt-level conventions), never schema-enforced. Two families of checks survive the refonte: corruption (states impossible through the write surface — `orphan_edges`, `invalid_metadata_json`, `status_without_bridge`, `hot_without_active`, `fts_integrity`, `file_permissions`) and consolidation (the closure gate — `no_hot`, `isolated_active`, `duplicate_titles`), each payable with the raw verbs; corruption introduced outside the library (hand SQL on a second connection) pays in SQL — the store's own connection is `#db`-private, no in-process raw access.

## Considered options

- **Port doctor 1:1 and drop finish's window checks** — the corruption detector survives, the ritual dies. Rejected: the checks the dev wanted gone were exactly the ones with no structural meaning (kind/window), but the closure gate's _purpose_ — force consolidation before leaving — was load-bearing; the two verbs were one activity split in two.
- **Keep finish as a thin composition over doctor** — after shedding its kind/window checks, finish had nothing left but a doctor pass-through with a different report shape: a catch-all that earns no place.
- **Keep kind-driven checks (`active_without_kind`, `stale_handoff`, the session obligations)** — the legacy machinery rode kinds the recover served structurally; post-hot, a kind check enforces a convention with no teeth. Rejected: the same debts recast kind-free (`no_hot` — the next recover must not serve an empty block; islands — the unexplored graph). The dream/evaluation vocabulary stays prompt-level.
- **Keep `DoctorOptions.fix` (in-store FTS rebuild)** — the only mechanical repair the legacy executed. Rejected: FTS drift can only come from manual SQL (the triggers maintain the index at every verb write), the agent never needs the repair, and the store must stay purely diagnostic — the hint names the one-line SQL, executed outside the library.
- **Keep `self_edges` as a doctor check over a permissive `link()`** — the legacy left a self-edge to land and flagged it. Rejected in favor of refuse-don't-hide: an edge from a memory to itself names no relationship, so `link()` refuses at the gate; the check dies with the possibility.
- **Keep `db` public (the white-box surface)** — with `fix` gone, nothing legitimate reads raw from the store's connection: the field closed behind `readonly #db`, and the tests reshape onto a second raw connection — the real-world hand-SQL vantage.

## Consequences

- The verb set on the store becomes: 7 writes, 5 reads (`get`, `list`, `search`, `recover`, `stats`), `checkout`, `fork`, `close`. The session rituals pair as Recover (entry) ↔ Checkout (exit).
- The all-or-nothing contract makes every finding a session-blocking debt: hints must always name a payable path — a verb where the state is agent-owned, SQL where corruption entered from outside.
- `isolated_active` fires only while ≥ 2 actives exist (a one-memory store is an atom, not an island) and aggregates the ids into one finding; `no_hot` stays silent when there is nothing to serve (no memories, no actives).
- The FTS rebuild route lives outside the library: a raw sqlite connection runs `INSERT INTO memories_fts(memories_fts) VALUES('rebuild')`; the manager CLI (fog) may compose its own repair command later.
- The server and MCP surfaces (port tickets in fog) expose the verdict, not the legacy doctor/finish split; the CLI re-homing table's `souv finish` is revised command by command at the CLI tickets.
- The removed surface (finish and its window checks, the kind checks, the `fix` option, the `self_edges` check) registers in the backlog with reactivation criteria ([Backlog: store surface — future tracks](https://github.com/souvenance-ai/souvenance/issues/28)).
