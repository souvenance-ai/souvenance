# The governance split: the checkout gate for the agent, the doctor audit for the operator

The governance layer rebuilds around one question the dev reframed mid-refonte: what forces an agent to close its session cleanly? The legacy split — a doctor diagnosing corruption and a finish gating the session's kind-based obligations — mixed two audiences in two vocabularies. v0.2.0 answers with two verbs, one per audience: **`checkout()`** — the agent's closure gate (Checkin's pair): the consolidation debts, every finding payable with the raw verbs, the green light (`healthy`, zero findings) always reachable; and **`doctor()`** — the operator's corruption audit: the states the write surface cannot produce (hand SQL on a second connection, external tools), every finding payable in SQL. Both verdicts are **all-or-nothing** (no severity — a debt either blocks or the store is green), **timeless** (no window), and **kind-free** (kinds are free metadata tags — prompt-level conventions, never schema-enforced). They are **independent**: checkout says nothing about corruption — a corruption finding would be a debt no verb can pay, and a blocking composition would weld the gate shut on a hand-corrupted store forever.

## Considered options

- **One fused verdict (checkout carries corruption + consolidation)** — tried in the first governance build: doctor and finish fused into a single checkout. Rejected: a corruption finding is a debt NO verb can pay (the repair route is SQL, outside the library — the store's connection is `#db`-private), so the all-or-nothing gate yields a permanent red light on a hand-corrupted store: the ritual can never close. The fusion insight survives the rejection — doctor and finish WERE one activity, and the kind/window checks died together — the audiences just split the verbs.
- **Port doctor 1:1 and drop finish's window checks** — the corruption detector survives verbatim, the ritual dies. Rejected: the checks the dev wanted gone were exactly the ones with no structural meaning (kind/window), but the closure gate's _purpose_ — force consolidation before leaving — was load-bearing.
- **Keep finish as a thin composition over doctor** — after shedding its kind/window checks, finish had nothing left but a doctor pass-through with a different report shape: a catch-all that earns no place.
- **Keep kind-driven checks (`active_without_kind`, `stale_handoff`, the session obligations)** — the legacy machinery rode kinds the legacy recover served structurally; post-hot, a kind check enforces a convention with no teeth. Rejected: the same debts recast kind-free (`no_hot` — the next checkin must not serve an empty block; islands — the unexplored graph). The dream/evaluation vocabulary stays prompt-level.
- **Composition between the verdicts (checkout composes doctor)** — blocking would recreate the unpayable findings; info-only would be a field the server exposes for nothing (the agent can do nothing with it). Rejected: independent verdicts, and the server/CLI surfaces (fog) decide what they display.
- **Keep `DoctorOptions.fix` (in-store FTS rebuild)** — the only mechanical repair the legacy executed. Rejected: FTS drift can only come from manual SQL (the triggers maintain the index at every verb write), the agent never needs the repair, and the store must stay purely diagnostic — the hint names the one-line SQL, executed outside the library.
- **Keep `self_edges` as a doctor check over a permissive `link()`** — the legacy left a self-edge to land and flagged it. Rejected in favor of refuse-don't-hide: an edge from a memory to itself names no relationship, so `link()` refuses at the gate; the check dies with the possibility.
- **Keep `db` public (the white-box surface)** — with `fix` gone, nothing legitimate reads raw from the store's connection: the field closed behind `readonly #db`, and the tests reshape onto a second raw connection — the real-world hand-SQL vantage.

## Consequences

- The verb set on the store is: 7 writes, 5 reads (`get`, `list`, `search`, `checkin`, `stats`), `doctor`, `checkout`, `fork`, `close`. The session rituals pair as Checkin (entry) ↔ Checkout (exit); the doctor is the manager's offline audit.
- The all-or-nothing contract makes every finding a blocking debt, and every finding payable by its own audience: the agent pays checkout's debts in verbs (`setHot`, `link`, `merge`, `supersede`, `deprecate`), the operator pays doctor's in SQL.
- `checkout`'s checks: `no_hot` (silence when there is nothing to serve — no memories, no living), `isolated_active` (fires only while ≥ 2 living memories exist — a one-memory store is an atom, not an island — and aggregates the ids into one finding), `duplicate_titles` — all three read the LIVING set (`active` + `hot`, #38): a hot memory owes its relations and its title as much as an active one. `doctor`'s: `orphan_edges`, `invalid_metadata_json`, `status_without_bridge`, `fts_integrity` (`VACUUM INTO` snapshot + fts5vocab diff + integrity-check, readable read-only), `file_permissions` (statSync, win32 skipped). The `hot_without_active` check retired with the hot column (#38): hot is a status now, and hot-on-a-terminal is unrepresentable — the contradiction it witnessed cannot be encoded, so there is nothing left to audit.
- The FTS rebuild route lives outside the library: a raw sqlite connection runs `INSERT INTO memories_fts(memories_fts) VALUES('rebuild')`; the manager CLI (fog) may compose its own repair command later.
- The server and MCP surfaces (port tickets in fog) expose `checkout` to agents and leave `doctor` to the manager; the CLI re-homing table's `souv finish` is revised command by command at the CLI tickets.
- The removed surface (finish and its window checks, the kind checks, the `fix` option, the `self_edges` check) registers in the backlog with reactivation criteria ([Backlog: store surface — future tracks](https://github.com/souvenance-ai/souvenance/issues/28)).
